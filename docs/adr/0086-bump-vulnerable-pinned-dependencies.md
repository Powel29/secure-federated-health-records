# ADR-0086: Bump vulnerable pinned dependencies (Django, cryptography, FastAPI/Starlette)

- **Status:** Proposed
- **Date:** 2026-10-19
- **Deciders:** Powel (proposal) -> Avaneeth (`deploy/`, `api/`), Ojas (`crypto_core`, `wire`) -> all four
- **Task / source:** whole-project check 2026-10-19, finding 2 (`docs/review/2026-10-07-fix-proposals.md`)
- **Affects:** `requirements.txt` (nothing else changes; no source edits were needed)

## Context

`pip-audit` over `requirements.txt` and the installed set reported known
vulnerabilities in three pins:

| Package | Pinned | Known vulnerabilities | Lowest clean version |
|---|---|---|---|
| Django | 5.0.6 (series out of support) | 43 | 5.2.17 (5.2 is the current LTS line) |
| cryptography | 42.0.5 | 11 | 50.0.0 (49.0.0 still has 2) |
| Starlette (via FastAPI 0.110) | 0.36.3 | 14 | 1.3.1 |

`httpx`, `uvicorn`, `psycopg`, `pandas`, `matplotlib` and `pyshark` were clean.
`cryptography` is the library behind every control in `crypto_core`, and
Starlette serves every federation service, so these are not cosmetic.

## Decision

Pin the latest audited-clean releases in `requirements.txt`:

- `Django==5.2.18` (was 5.0.6)
- `cryptography==50.0.2` (was 42.0.5)
- `fastapi==0.148.0` (was 0.110.0)
- `starlette==1.9.0`, newly pinned. It was an unpinned transitive dependency, so
  the audited version was not necessarily the installed one.

No source change was required. Checked in a fresh Python 3.11 venv from
`requirements-dev.txt`: 950 passed / 3 skipped (with Postgres), the 85 portal
tests, `ruff` and `black` clean, `tests.security.mutations` exits 0, and
`pip-audit -r requirements.txt` reports no known vulnerabilities.

## Alternatives considered

- **Stay on the 5.0 / 42 / 0.110 line and patch within it.** Rejected: Django 5.0
  no longer receives fixes, and the fixed `cryptography` and Starlette versions
  are only in later series.
- **Stop at `cryptography` 46.x or 48.x.** Rejected: both still carry known
  vulnerabilities; 50.0.0 is the first clean release, and the tests pass on it.
- **Leave Starlette transitive.** Rejected: a floating transitive pin can
  silently reintroduce a vulnerable version.

## Consequences

- **Evidence must be regenerated.** Timings in `bench/results/` were measured on
  the old libraries. Re-run `python -m bench.run_benchmarks` before quoting
  latencies, and re-record the captures before the Stage 4 run.
- Everyone must rebuild their environment (`pip install -r requirements-dev.txt`);
  an old venv keeps the vulnerable versions.
- Existing portal migrations were generated by Django 5.0.6 and still apply;
  no new migration was needed.
- `pip-audit` is not in CI. Adding it as a scheduled job is a follow-up.
